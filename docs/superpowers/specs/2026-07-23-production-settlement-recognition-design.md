# 商场结算单生产级识别设计

## 目标

在现有 Demo 中把“结算单智能识别”建设为可独立试运行的业务模块。系统自动完成识别、字段映射、明细还原和勾稽校验；财务人员只处理异常项，正常单据可以一键确认。第一阶段不允许未经人工确认直接写入 ERP。

## 验收边界

- 支持扫描 PDF 和图片型 PDF，不依赖 PDF 文本层。
- 不针对单一商场或单一模板写死字段位置和金额。
- 汇总金额、单号、日期、商户主体等关键字段必须经过独立双读。
- 任一关键字段发生冲突、缺失或勾稽不一致时，禁止确认。
- 明细必须区分业务行、调整行、小计、合计和空白占位区域。
- 财务可以从字段或明细行跳转到原始 PDF 对应区域复核。
- 人工修改后必须重新执行规则校验，校验通过后才能确认。
- 保存原始结果、二次结果、人工修改、确认人和模型版本，形成审计记录。

## 推荐架构

采用“OCR/文档解析 + 视觉 LLM + 确定性规则”的三层架构。

1. 文档解析层负责页面渲染、图像预处理、文字与表格单元格识别，并返回页码和坐标。
2. 视觉 LLM 层负责理解不同商场的版式、区块语义、字段含义和表格层级，不负责最终决定金额是否可信。
3. 规则层负责格式、行数、重复、合计、公式和跨区勾稽，产生可解释的通过或阻断结果。

纯视觉 LLM 保留为识别能力之一，但不再以模型自报置信度作为生产放行依据。未来可以增加第二家视觉模型作为关键字段仲裁器，但第一阶段先用独立裁剪复读和 OCR 交叉验证。

## 数据流

1. 用户上传原始 PDF，后端生成文件指纹并创建识别任务。
2. 页面级渲染保留完整图像，同时生成适合小字和表格的高清切片。
3. OCR/文档解析返回文字、表格单元格、页码和坐标。
4. 视觉 LLM 识别单据元数据、汇总区、销售/进货明细、扣费明细和其他区块。
5. 标准化层将不同商场标签映射到统一业务字段，但同时保留原始标签和值。
6. 关键字段使用独立图像裁剪重新读取，并与首轮结果和 OCR 结果比较。
7. 完整性引擎检查区块、表头、明细行、合计行、空白区域和重复行。
8. 规则引擎执行金额及数量勾稽，输出通过、警告或阻断。
9. 前端只聚合展示异常项；用户可查看原图证据并修改。
10. 修改后重新校验。不存在阻断项时允许确认，并写入审计记录。

## 关键字段双读

以下字段无论首轮置信度多高都必须复读：结算单号、商场、品牌/商户、柜号/门店编码、结算月份或日期、销售金额、销售数量、发票金额、扣费合计、实付金额。

双读结果分为：

- `confirmed`：字符级标准化后完全一致，可以作为自动通过证据之一。
- `conflict`：结果不一致，保留首轮值和二次值，阻断确认。
- `unresolved`：图像无法可靠读取，阻断确认并要求人工录入。

二次结果不得静默覆盖首轮结果。模型置信度只用于排序，不用于决定是否放行。

## 明细完整性

每个识别区块保存：区块标题、原始表头、标准化列、所有可见行、行类型、页码、坐标和识别来源。

完整性检查包括：

- 表头是否存在且列数是否合理。
- 可见业务行是否全部输出。
- 小计和合计是否被误算为业务行。
- 空白行是否被误认为漏识别。
- 行序号是否连续，是否存在重复行。
- 明细合计是否与原单打印的小计/合计一致。
- 汇总区金额是否与明细合计一致。

系统必须区分“原单该区域为空”和“该区域未成功识别”，两者不能都显示为无数据。

## 复核界面

保留当前按业务区块展示的工作台，增加：

- 顶部任务状态：解析中、双读中、待复核、可确认、已确认、识别失败。
- 异常队列：冲突、缺失、勾稽不一致、完整性异常按风险排序。
- 原图证据面板：点击字段或明细行后显示对应页面和框选区域。
- 双结果对比：首轮值、独立复读值、OCR 原文并排展示。
- 修改原因：人工修改关键字段时必须填写原因。
- 确认门禁：存在阻断项或校验未重跑时，确认按钮不可用。

正常字段保持紧凑展示，避免让财务逐项点击确认。

## 错误处理

- 模型或 OCR 超时：任务保留并允许重试，不丢失已经完成的阶段结果。
- 非 JSON 或字段结构异常：后端拒绝写入标准结果，记录原始响应用于排查。
- 页数或图片过大：分批处理并显示进度，不在浏览器中一次提交全部大图。
- 结果冲突：进入异常队列，不自动选择任何一方。
- 未知模板：允许识别，但标记为新格式并提高复核等级。

## 审计与安全

- API Key 仅保存在后端环境变量中。
- 原文件使用哈希去重并关联识别任务。
- 保存模型名称、提示词版本、OCR 引擎版本、规则版本和每次结果。
- 保存人工修改前后值、修改原因、操作人和时间。
- 日志不得记录 API Key，也不应完整输出包含敏感数据的模型请求。

## 测试与上线标准

建立脱敏回归样本集，初期至少覆盖 30 至 50 份、多个商场和多种清晰度。每份样本具备人工标注的字段和明细真值。

第一阶段试运行标准：

- 核心金额字段字符级准确率达到 99.5% 以上。
- 关键字段未检出的情况必须被阻断，漏报率为 0。
- 明细业务行完整率达到 99% 以上。
- 所有公式不一致均能被规则引擎识别。
- 任何模型或解析失败均不得生成“可确认”状态。
- 当前 SHAD64 样本的汇总、9 个有效销售/调整业务行语义、A/B/C 扣费分组和所有有值费用项完整还原。

## 分阶段交付

### 第一批：风险控制闭环

关键字段无条件双读、完整性审计、异常模型、确认门禁和审计事件。这一批完成后，现有样本可以在人工兜底下试运行。

### 第二批：证据复核闭环

接入 OCR/文档解析坐标，增加 PDF 原图框选、首轮/OCR/复读对比和人工修改后重算。

### 第三批：规模化适配

建立样本真值库和自动回归报告，加入未知模板检测、任务队列、部署监控及后续 ERP 接口。

## 非目标

- 第一阶段不做无人值守自动记账。
- 第一阶段不承诺所有未知商场格式自动通过。
- 不把中转站 API Key 或模型调用放到浏览器。
- 不为 SHAD64 单据写死坐标、金额或字段内容。
